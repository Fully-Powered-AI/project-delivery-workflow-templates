## What was observed

Every required part was produced, and no stop condition applied: the headings matched, the weights total 100, the month headings agree and every role has a capacity row. The stop conditions and the acceptance tests were not run.

Differences from the published example:

- The scores, the ranking, the loads, the over-ceiling amounts, the start-month tests and the room figures matched the published example, and so did the proposal's place (third of five). The differences are in wording only: the proposal summary and the first gap are phrased a little differently.
- Value 4 followed from the revised input, which now says the 46 threads were counted in the shared booking inbox; I read a count of threads in the agency's own inbox as a count from its own records.
- Strategic fit 4 rested on G1 only. The proposal's words about retained clients connect it to G1; it claims no saving, so G2 was not counted, and I put the question about G2 in the gaps, as the added line in step 3 directs.
- I wrote the May booking season without a year, as the inputs do.

Points where the template still leaves a choice:

- "1.0 days of room" reads awkwardly beside "n days of room" in the output format; I kept the format's wording.
- Whether a later reader would score "directly" and "indirectly" as I did depends on the added line in step 3 being applied the same way; it was applied once, by the same session that wrote it.

## What came before

An earlier run on the previous version gave Value 3 (weighted 3.10) because the proposal did not say where the count came from, quoted nothing for Strategic fit, and left open whether a row of 0 days counts as using a role, which projects the higher-or-lower line covers, and how days are shown. The example's year "2027-05" had also been added without support in the inputs. After that run the proposal input was made to say where the count came from, the example's "2027-05" became "the May booking season", the Strategic fit evidence now quotes the proposal, the template settled the other points (a 0-day row is left out; the line covers the listed projects, fixed work included; days are shown to one decimal; the proposal is shown at its rank), and rules that sat only in the prose were added to the instruction block. This run is of that revised version.

No instruction told me to stop on these inputs. Every fact in my output is in the inputs supplied, apart from the arithmetic derived from them.

This run adds a single trial on an invented example to the template's record; it is not a test in a client environment.

## Changes made after this run

After an independent review, the instructions and the example were amended in small ways: the instruction block now carries the input checks (every ID in the days table is in the project list, no ID twice, the projects counted before and after), the note that running totals assume a whole month's release, and the room-against-asked line for the wanted start; one missing score now stops the review before ranking; a role with no capacity row stops the work; and the published example's header, a covering sentence and its closing line ("the five inputs above" became "the inputs supplied", as the format fixes it) were aligned to the output format, and its sentence about the 0-day Developer row was removed. The run recorded above was not repeated on the amended instructions. The recorded output is unchanged, so it differs from the published example in those few lines (the header wording, "Releasing P1 covers the 7.0 days" and the sentence about P2's 0-day row). None of the amendments alters a figure, a score or a ranking.
